# Any Research (mindustry mod, build 160.x)

Позволяет исследовать дерево технологий в мультиплеере не только хосту, но и любому
игроку, **у которого стоит этот мод**. У кого мода нет — исследовать не может
(но играть может). Исследование идёт **по правилам ванильного дерева**: проверяются
условия узла, предыдущие исследования и списывается стоимость из запаса.

## Установка

- себе (клиент): `%APPDATA%\Mindustry\mods\any-research.jar`;
- на обычный выделенный сервер: `<папка сервера>/config/mods/any-research.jar`;
- **в MP-Sectors**: на сервер ставить НЕ нужно — серверная половина уже встроена в
  `mp-sectors` (иначе команда зарегистрируется дважды). Достаточно клиентского jar.

## Использование

- Гость с модом кликает по узлу дерева. Сервер отвечает в чат одним из:
  - `Исследовано: <название> (списано: copper 25)` — ресурсы ушли из запаса;
  - `Не хватает ресурсов: silicon 40/120, graphite 0/50` — чего именно и сколько не хватает;
  - `Условия ещё не выполнены: исследовать lead, пройти сектор frozenForest` — узел ещё закрыт;
  - `Сначала исследуйте: <название>` — не выполнено предыдущее исследование.
- Хост исследует как обычно, мод ему не мешает.
- Консоль сервера: `anyresearch <название>` (то же самое, что делает игрок) и
  `anyresearch-status [название]` (диагностика).

## Правила, по которым работает исследование

Как в ванильном дереве (см. `ui/dialogs/ResearchDialog.java`):

- **Условия узла** (`TechNode.objectives`): узел нельзя открыть, пока не выполнены все
  его условия. Именно это не даёт открыть предметы (их получают добычей) и сектора
  (их получают высадкой) — такие узлы закрыты своими условиями.
- **Предыдущие исследования**: цепочка родителей должна быть исследована.
- **Стоимость**: списывается из того же запаса, что показывает игра — базовые сектора
  планеты узла, текущий сектор последним. Если не хватает — исследование отменяется,
  ничего не списывается. После списания код проверяет, что запас реально уменьшился,
  иначе исследование не выдаётся: **бесплатно открыть узел нельзя**.

## Что было исправлено после первой версии

1. Ресурсы на исследование у гостя теперь видно дважды: под названием узла при наведении
   появляется своя строка `Нужно: copper 25, lead 10` (ваниль на клиенте вместо списка
   требований рисует просто `@locked` — `ResearchDialog.java:677`), а по клику сервер
   присылает точные цифры «сколько есть / сколько надо». Панель запаса при этом
   сознательно не включается: на клиенте `Sector.items()` возвращает **сохранённый** запас
   сектора, а не текущий (`Sector.java:235-247`, `isBeingPlayed()` требует `!net.client()`),
   так что она показывала бы устаревшие числа и не менялась бы после исследования.
2. Раньше можно было открыть любой узел — теперь проверяются предыдущие исследования.
3. Раньше ресурсы не списывались — теперь списываются (и проверяется, что списание прошло).
4. Раньше открывались предметы и сектора — теперь их закрывают их же условия.

## Проверено / не проверено

Проверено вживую (headless-сервер `server-release.jar` 160.4, итоговый jar):

- мод грузится, `hidden=true`, список модов для клиентов пуст → ванильные коннектятся;
- `Не хватает ресурсов: copper 0/5` — ценник проверяется;
- `Условия ещё не выполнены: исследовать lead, исследовать coal, пройти сектор frozenForest` — условия и предки проверяются.

Не проверено (нужна кампанийная игра, которую хостит клиент; выделенный сервер
кампанию не хостит — `ServerControl.java:1173,1199` намеренно обнуляет `rules.sector`):

- реальное списание из запаса и успешное исследование. Проверь: кликни узел, который
  можешь себе позволить, и в чат должно прийти `Исследовано: ... (списано: ...)`.

## Ограничения (осознанные)

- Оплата только полная за раз: накопление прогресса по частям не поддерживается.
  Уже оплаченная хостом часть узла (`TechNode.finishedRequirements`) учитывается —
  гость доплачивает только остаток, двойного списания нет.
- Гейт «только с модом» — константа внутри jar, а не защита от подделки.
- Мод привязан к сборке 160.x.

## Сборка

```powershell
cd any-research
.\build.ps1 -GameJar ..\client\libs\Mindustry.jar
```

Нужен JDK 17+ и `Mindustry.jar` (desktop). Если он лежит в `client\libs`, путь можно
не указывать — скрипт найдёт его сам.
